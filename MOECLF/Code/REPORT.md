# MOECLF 复现报告

对 Wu 等 (2025)《Multi-objective evolutionary co-learning framework for energy-efficient
hybrid flow-shop scheduling》的独立复现报告。

> 本报告为**独立复现**，非原作者代码。实现依据论文公式与流程图完成，
> 与原文的差异及未对齐之处见第 5 节。

---

## 1. 问题与实验设置

### 1.1 问题

EHFSP-HMC：带人机协同与疲劳效应的能效混合流水车间调度。双目标最小化：

- `Cmax`：最大完工时间
- `TEC`：总能耗（setup + processing + idle + 公共能耗）

决策变量为三层编码：作业排序 `job_seq`、机器分配 `mach`、工人分配 `worker`。
工人存在疲劳累积（`lam`）与恢复（`mu`），通过 `delta` 影响实际处理时间。

### 1.2 算例

官方 `EHFSP-HMC.json` 共 90 个实例，覆盖 J15/J30/J45 三档作业数、2/4/6 阶段。
实验选用 6 个代表实例：

```
J15-S2-1  J15-S4-1  J30-S2-1  J30-S4-1  J45-S4-1  J45-S6-1
```

疲劳影响因子取主实验档位（`delta_idx=0`，`0.3/ln2`）。

### 1.3 参数（论文 Table 5 / Table 8）

| 参数 | 取值 |
|---|---|
| 种群 `Np` | 200 |
| 迭代 `Ngen` | 1000 |
| 随机种子 | 0–4（5 个） |
| PPO 学习率 / `gamma` / `lambda` | 0.001 / 0.98 / 0.98 |
| PPO clip / epochs / batch | 0.2 / 10 / 128 |
| `c_theta` / `c_phi` / `c_entropy` | 2.0 / 1.0 / 0.01 |
| Q-learning `alpha` / `gamma` / `eps` | 0.15 / 0.98 / 0.4 |
| NSGA-II `Cr` / `Mr` | 0.8 / 0.2 |
| FSM 输入尺寸 | 46 × 46 |

每个 (算法, 实例, 种子) 组合独立运行，取最终种群的非支配前沿计算指标。
共 6 实例 × 5 种子 = 30 个样本/配置。

### 1.4 指标

- **HV**（超体积，式 46）：主指标，越大越好
- **GD**（世代距离，式 42）：收敛性，越小越好
- **IGD**（反世代距离，式 44）：收敛 + 多样性，越小越好
- **C**（集合覆盖率，式 40）：行算法支配列算法的解比例
- **Wilcoxon rank-sum**：论文 Table 13 所用检验，`alpha = 0.05`

指标均基于 min-max 归一化后的目标矩阵计算。

> **注意**：归一化参考集在每个实验内各自构造。因此**跨表比较绝对值无意义**，
> 只能引用同一张表内的对比。这一点在第 5 节列为已知局限。

## 2. 实验设计

| 实验 | 目的 | 配置 |
|---|---|---|
| **实验1 消融** | 各模块贡献 | v1 → v2(+MSI) → v3(+VNS) → v4(+EP) → MOECLF(+PPO) |
| **实验2 控制器** | 学习型控制器的价值 | Random / Q-only / PPO+Q |
| **实验2 预训练** | 补足 PPO 样本后是否改善 | 跨 10 实例预训练 → 冻结策略测试 |
| **实验3 算法** | 与主流多目标算法对比 | MODJA / NSGA-II / MOEQLF / MOECLF |
| **实验3 预训练** | 同上，预训练版 | 同上 |
| **实验A 上限**（新增） | 边界位置是否存在提升空间 | Oracle 完美选择器 |

### 2.1 关于实验 A

实验 A 是复现过程中**额外加入的诊断实验**，原文没有。

MOECLF 中 200 个个体分工如下（`moeclf.py`）：

```
200 个个体
├── 198 个 → Q-learning
└──   2 个 → PPO   （F1 上拥挤距离最大的边界个体 BI）
```

因此 PPO 的全部职责是：给这 2 个个体从 10 个 LLH 中挑一个。
"PPO 没赢"有两种可能解释：**学得不好**，或**这个位置本身没价值**。

Oracle 用于区分两者：它不学习，而是对每个边界个体**枚举全部 10 个 LLH**，
实际执行、解码、计算 reward，取 reward 最大者。这代表"如果 PPO 每次都能选对，
最好能到什么程度"——该位置的理论上限。

代价是每步 10 次解码，约为常规 run 的 10 倍计算量。

### 2.2 关于"预训练"

此处的预训练**不是**迁移学习意义上的预训练：`FSMPolicy` 为手写 MobileNetV2 +
kaiming 随机初始化，未加载任何外部权重。

它指强化学习意义上的**跨 episode 累积经验**：

```
Phase A: 在 J45-S6-1..10 上各跑 1 个 episode（Np=200/Ngen=1000）
         PPO agent 与 Q 表跨 episode 共享、不重置
Phase B: 加载策略，在 6 个实例上测试（train=False，冻结）
```

对比普通版：`_moeclf()` 每次调用新建 agent，每个 (实例, 种子) 从零学起、跑完即弃。

预训练的目的是给 PPO 一次**公平机会**：PPO 每代只处理 ≤2 个个体，
单次 run 仅约 2000 条样本；预训练 10 个 episode 后约 2 万条，放大 10 倍。
用于排除"样本不足"这一解释。

## 3. 结果

### 3.1 实验1：消融

**HV 均值（6 实例 × 5 种子）**

| 配置 | HV 均值 | 相对上一版 | p |
|---|---:|---:|---:|
| v1 基线 | 0.3177 | — | — |
| v2 +MSI | 0.4102 | +0.0925 | 4.22e-04 ✅ |
| v3 +VNS | 0.3933 | **−0.0169** | 4.46e-01 ❌ |
| v4 +EP (=MOEQLF) | **0.8577** | **+0.4644** | 3.02e-11 ✅ |
| MOECLF +PPO | 0.8643 | +0.0066 | 6.84e-01 ❌ |

**逐实例 HV**

| 实例 | v1 | v2(+MSI) | v3(+VNS) | v4(+EP) | MOECLF |
|---|---:|---:|---:|---:|---:|
| J15-S2-1 | 0.466 | 0.493 | 0.430 | 0.854 | 0.853 |
| J15-S4-1 | 0.300 | 0.357 | 0.353 | 0.791 | 0.827 |
| J30-S2-1 | 0.399 | 0.439 | 0.423 | 0.853 | 0.871 |
| J30-S4-1 | 0.296 | 0.450 | 0.431 | 0.839 | 0.864 |
| J45-S4-1 | 0.296 | 0.406 | 0.416 | 0.903 | 0.887 |
| J45-S6-1 | 0.149 | 0.316 | 0.307 | 0.906 | 0.884 |

**覆盖率 C**：v4 与 MOECLF 对 v1/v2/v3 均为 **1.000**（完全支配）；
MOECLF 对 v4 为 0.433，v4 对 MOECLF 为 0.321。

**解读**

1. **EP 是唯一的主要贡献**，单项带来 +0.46 HV，且在 6 个实例上全部为正。
2. **MSI 有中等贡献**（+0.09，显著）。
3. **VNS 无贡献**：v2→v3 为负、p=0.45。逐实例看，VNS 在 4 个实例上小幅提升
   （J15-S4-1、J30-S2-1、J30-S4-1、J45-S4-1），但在 J15-S2-1 上从 0.493 掉到 0.430，
   拉低整体均值。这一模块在论文中难以交代。
4. **PPO 未带来增益**：MOECLF vs v4，p=0.68。

## 4. 结论

### 4.1 站得住的正面结论

| 结论 | 强度 |
|---|---|
| **EP（精英保留）是主要贡献**：HV +0.46，p=3.0e-11 | 强 |
| **MSI 有中等贡献**：HV +0.09，p=4.2e-4 | 强 |
| **MOECLF/MOEQLF 显著优于 MODJA、NSGA-II**：C 达 0.998，p≈3e-11 | 强 |

### 4.2 站得住的负面结论

| 结论 | 证据 |
|---|---|
| **VNS 无贡献** | v2→v3 HV −0.017，p=0.45 |
| **PPO 无贡献** | 实验1 p=0.68；实验2 低于 Random p=0.030；预训练后更差 p=6.9e-4；实验3 预训练版显著更差 p=0.047 |
| **2/200 边界位置不是瓶颈** | Oracle 仅 +0.029，p=0.219，且低于 Random 0.032 |
| **奖励函数梯度稀疏** | reward=+2 占比 0.7%–2.6%；J45-S4-1 平均最优 reward 为负 |

### 4.3 对论文核心创新点的判断

论文的核心创新是"PPO + Q-learning 双智能体协同"。复现结果在四条独立路径上
一致地不支持这一模块的增益：

```
实验1（常规）      MOECLF 0.864 vs MOEQLF 0.858    p=0.68   无差异
实验2（常规）      PPO+Q 0.675 vs Random 0.718     p=0.030  更差
实验2（预训练）    PPO+Q 0.621 vs Random 0.722     p=6.9e-4 更差
实验3（预训练）    MOECLF 0.790 vs MOEQLF 0.828    p=0.047  显著更差
实验A（上限）      Oracle 0.689 vs Random 0.721    p=0.219  更差
```

**"样本不足"这一解释已被排除**：预训练把样本量放大 10 倍后差距反而扩大。

**更根本的原因在结构**：PPO 只作用于 2/200 的个体，即使做到完美选择也无增益；
且奖励函数中真正表示改进的 `+2` 仅占 0.7%–2.6%，无法提供学习方向。

建议论文表述：

> 即便给予跨 10 个实例、约 2 万条经验的预训练（PPO 单 run 样本量的 10 倍），
> PPO 控制器仍未优于随机控制器；上限实验进一步表明，将边界个体的动作选择
> 替换为穷举最优解亦无显著提升。这说明性能瓶颈不在样本量或学习能力，
> 而在 PPO 仅作用于 2/200 边界个体的结构设计，以及奖励函数的稀疏性。

## 5. 与原文的差异和已知局限

### 5.1 已知偏差

| 项目 | 原文 | 本复现 | 影响 |
|---|---|---|---|
| **预训练测试集** | 必须是 unseen 实例 | 含 `J45-S6-1`，它在训练集内 | ⚠️ 见下 |
| 运行设备 | 服务器 GPU | 本地 CPU | 不改变算法语义 |
| 统计样本量 | 未明确 | 6 实例 × 5 种子 | 检验功效偏小 |

**训练/测试集重叠**：`run_pretrain.py` 的 `TRAIN_INSTANCES = J45-S6-1..10`，
而 `TEST_INSTANCES` 也包含 `J45-S6-1`。该实例被完整训练过 1 个 episode 后又用于测试。

按当前结论这不影响判断（J45-S6-1 上 PPO+Q 的 HV 为 0.642，仍低于 Random 的 0.830），
但**不能基于预训练版的数字论证任何正向结论**。若要修正，只需从测试集剔除该实例，
Phase A 无需重跑。

### 5.2 统计与方法局限

1. **n=6 的检验功效弱**。p=0.219 只说明"没有证据显示有增益"，不能断言"绝对无增益"。
   但结合方向为正却极小、且 Oracle 低于 Random，结论仍成立。
2. **归一化参考集各实验独立构造**，导致同一配置在不同表中的绝对值不同
   （如 J15-S2-1 的 Random：实验2 为 0.762，实验A 为 0.7487）。
   横向跨表比较无意义，需统一参考集才能比较。
3. **实验A 的 Oracle 是即时贪心**：每步只看当前 reward，不考虑长期 HV 影响。
   它是"贪心意义下的上限"，非全局最优。
4. **实验A 只接管 2/200 个体**，测的是"该位置的上限"，不是"PPO 的能力上限"。

### 5.3 未完成的实验

**实验 B（PPO 全权控制）**：让 PPO 接管全部 200 个个体，样本量从约 2000 提到约 20 万，
用于区分"PPO 学不动"与"2/200 位置无价值"。**该实验未产出结果，相关代码已在整理时移除**，
本仓库不包含实验 B 的实现。

停止原因是算力：基准测试显示 PPO 单次前向约 12 ms，若处理
200 × 1000 = 20 万个体，仅推理即约 40 分钟；叠加 10 epoch 反向传播，
单 run 约 11 小时，30 个 run 需约 37 小时，在 CPU 上不可行。

若要继续，需先解决算力（GPU 加速）或缩小 `Ngen` 做诊断。

### 5.4 关于预训练表中非学习算法

`run_pretrain.py` 的 Random / MODJA / NSGA-II 直接复用 `run_experiments` 的缓存。
逻辑上没有问题（非学习算法本就没有"预训练"概念，且规模相同），
但论文中应注明，避免读者误以为对比基线也做了同样处理。

## 6. 复现说明

### 6.1 环境
