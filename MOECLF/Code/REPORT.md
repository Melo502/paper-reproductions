# MOECLF 复现报告

对 Wu 等 (2025)《Multi-objective evolutionary co-learning framework for energy-efficient
hybrid flow-shop scheduling》的独立复现报告。

> 本报告为**独立复现**，非原作者代码。实现依据论文公式与流程图完成。
> 复现严格遵循论文的两阶段协议（训练阶段 → 测试阶段），
> 与原文的差异及已知局限见第 5 节。

## 1. 问题与实验设置

### 1.1 问题

EHFSP-HMC：带人机协同与疲劳效应的能效混合流水车间调度。双目标最小化：

- `Cmax`：最大完工时间
- `TEC`：总能耗（setup + processing + idle + 公共能耗）

决策变量为三层编码：作业排序 `job_seq`、机器分配 `mach`、工人分配 `worker`。
工人存在疲劳累积（`lam`）与恢复（`mu`），通过 `delta` 影响实际处理时间。

### 1.2 算例

官方 `EHFSP-HMC.json` 共 90 个实例，覆盖 J15/J30/J45 三档作业数、2/4/6 阶段。

- **训练实例**：`J45-S6-1` … `J45-S6-10`（10 个，45 工件 / 6 阶段）
- **测试实例**：6 个代表实例，覆盖不同规模与阶段数

```
J15-S2-1  J15-S4-1  J30-S2-1  J30-S4-1  J45-S4-1  J45-S6-1
```

疲劳影响因子取主实验档位（`delta_idx=0`，`0.3/ln2`）。

### 1.3 参数（论文 Table 5 / Table 8）

| 参数 | 取值 |
|---|---|
| 种群 `Np` | 200 |
| 迭代 `Ngen` | 1000 |
| 训练 episodes | 10 |
| 随机种子 | 0–4（5 个） |
| PPO 学习率 / `gamma` / `lambda` | 0.001 / 0.98 / 0.98 |
| PPO clip / epochs / batch | 0.2 / 10 / 128 |
| `c_theta` / `c_phi` / `c_entropy` | 2.0 / 1.0 / 0.01 |
| Q-learning `alpha` / `gamma` / `eps` | 0.15 / 0.98 / 0.4 |
| NSGA-II `Cr` / `Mr` | 0.8 / 0.2 |
| FSM 输入尺寸 | 46 × 46 |

每个 (算法, 实例, 种子) 组合独立运行，取最终种群的非支配前沿计算指标。
共 6 实例 × 5 种子 = 30 个样本/配置。

### 1.4 指标

- **HV**（超体积，式 46）：主指标，越大越好
- **GD**（世代距离，式 42）：收敛性，越小越好
- **IGD**（反世代距离，式 44）：收敛 + 多样性，越小越好
- **C**（集合覆盖率，式 40）：行算法支配列算法的解比例
- **Wilcoxon 秩和检验**：论文 Table 13 所用检验，`alpha = 0.05`

指标均基于 min-max 归一化后的目标矩阵计算。

> **注意**：归一化参考集在每个实验内各自构造。因此**跨表比较绝对值无意义**，
> 只能引用同一张表内的对比。这一点在第 5 节列为已知局限。

## 2. 两阶段实验协议

论文的协同学习框架由**训练阶段**与**测试阶段**组成，本复现严格按此执行。

### 2.1 训练阶段

在 10 个训练实例上依次运行，**同一组智能体跨实例共享、不重置**，
使经验在实例之间累积：

```
for ep, inst in enumerate(TRAIN_INSTANCES):     # J45-S6-1 .. J45-S6-10
    solver = MOECLF(inst, Np=200, Ngen=1000, ppo=ppo, q_agent=q, seed=ep)
    solver.run(train=True)                       # 参数在线更新
# 训练结束后保存 Q 表与两个 PPO 的策略网络
```

这一阶段对应论文所述「从已有实例积累经验」：
Q 表与 PPO 策略在 10 个实例上被反复更新，训练结束时固化为一份可迁移的策略。

### 2.2 测试阶段

载入训练阶段得到的策略，在 6 个测试实例上运行，**参数冻结**：

```python
solver.run(train=False)     # 只做前向决策，不再更新 Q 表与网络
```

`train=False` 关闭的仅是参数更新（`moeclf.py` 中两处 `update` 调用），
策略本身仍按各自机制产生动作：Q-learning 保留 `eps=0.4` 的探索，
PPO 按策略分布采样。也就是说，测试阶段衡量的是**训练所得策略的泛化表现**，
而非其确定性输出。

### 2.3 为什么必须是两阶段

控制器的作用是「在不同状态下选择不同算子」，其价值只有在
**策略固定、面对新实例**时才能被公平衡量：

- 若在每个测试实例上现场学习，则每个 (实例, 种子) 都从零开始，
  测到的是「1000 代内的在线适应能力」，而非论文主张的**跨实例迁移**。
- 论文强调的自适应是**状态依赖**（PPO 看 FSM、Q-learning 看上一个算子），
  并以训练阶段积累的经验指导新实例的进化。

因此本复现只保留两阶段协议的实验结果。

## 3. 算法设计说明

三个被比较的控制器，设计目标各不相同。

### 3.1 共同的框架

三者共享完全相同的 MOECLF 进化框架，只在「**由谁选择算子**」这一点上不同：

| 组件 | 三者是否一致 |
|---|---|
| 多策略初始化 MSI（9 条规则组合） | ✅ |
| 算子池：3 个遗传算子 + 7 个 VNS 局部搜索算子（LLH1–10） | ✅ |
| 非支配排序 + 拥挤距离 | ✅ |
| 交叉父代选择（Algorithm 5） | ✅ |
| 精英保留 EP | ✅ |
| **算子选择策略** | ❌ 差异所在 |

因此三者的差异可干净地归因于「算子选择」，这也是把它们放在同一组实验中的原因。

### 3.2 Random：随机算子选择（下界参照）

**设计**：每个个体每代从 10 个 LLH 中**均匀随机**抽取一个执行，不接收奖励、不更新任何参数。

```python
if self.controller == "random":
    action = int(self.rng.integers(0, self.n_actions))   # 10 选 1，等概率
    ...
    offspring.append(new_sol)      # 无 reward()、无 update()
```

**为什么这样设计**：

1. **界定「学习」的真实增益**。它保留了完整的 MOECLF 框架（MSI/VNS/EP/交叉选择），
   只把算子选择换成随机。因此 `Random` 与学习型控制器之间的差距，
   就是「算子选择策略」这一项的净贡献，不会被框架本身的强度掩盖。
2. **它控制全部 200 个个体**（不是只控制 2 个边界个体）。
   这一点在解读结果时很关键：`Random` 与 `PPO+Q` 的差异同时包含
   「有无学习」和「控制范围」两个因素，不能全部归因于 PPO。
3. **注意命名**：它不是经典意义上的 Random Search（随机生成解、择优保留），
   而是**随机算子选择**。正文中应写「Random LLH selection」或「随机算子选择基线」。

### 3.3 Q-learning：表格型控制器（承担 198/200）

**设计**：状态 = 上一步执行的算子（0–9），动作 = 下一步算子（0–9），
Q 表为 **10 × 10 = 100 格**。ε-贪心（`eps=0.4`）探索，
更新式 `Q[s,a] += alpha * (r + gamma * max Q[a,:] - Q[s,a])`。

**为什么选 Q-learning 而非深度网络**：

1. **样本效率**。它每代负责 200 个个体中的 198 个，单个 episode 即产生约
   20 万次更新。100 格的表在这个量级下会迅速收敛；若换成百万参数的深度网络，
   同样样本量远不足以训练。
2. **状态空间本就很小**。「上一步算子」只有 10 种取值，
   用表格可以精确表示，无需函数近似。
3. **与 PPO 形成互补分工**。它负责数量占绝对多数的普通个体，
   追求稳定、廉价的决策；PPO 负责少数关键个体，追求更强的状态感知。

**代价**：状态只看「上一个算子」，不含调度状态与目标值信息，
因此它对问题结构的感知很弱——这也是它在实验中未能超过随机的原因之一（见 4.2）。

### 3.4 PPO+Q：双智能体协同（论文核心创新）

**设计**：200 个个体按角色分工，PPO 只接管**边界个体（BI）**：

```
200 个个体
├── 198 个 → Q-learning
└──   2 个 → PPO        （F1 前沿上拥挤距离最大的 2 个）
```

两个 PPO agent 分别负责 `Cmax` 较小与较大的两端，各配一个
**手写 MobileNetV2**（约 2.2M 参数），输入为 **46 × 46 的 FSM 图像**
（行 = 机器 + 工人状态，列 = 作业 + 目标值），输出 10 个算子的策略分布。

**为什么让 PPO 只负责 2 个边界个体**：

1. **边界个体决定前沿的覆盖范围**。F1 上拥挤距离最大的个体位于前沿两端，
   它们向目标空间的稀疏区域延展，直接决定 HV 的上界。
   把最强的决策能力放在这里，是「好钢用在刀刃上」的设计。
2. **PPO 需要丰富的状态信息**。FSM 图像编码了机器负载、工人疲劳、
   目标值等全局状态，这类高维输入适合用卷积网络处理；
   而 198 个普通个体若也走 PPO，算力开销无法承受（单次前向约 12 ms）。
3. **奖励设计对应帕累托改进**（式 38）：

   | 子代相对父代 | reward |
   |---|---|
   | 子代支配父代 | **+2** |
   | 父代支配子代 | **−1** |
   | 互不支配 | **+1** |
   | 完全相同 | 0 |

   该奖励直接编码「是否带来帕累托改进」，与多目标优化的目标一致。

**代价**：PPO 的作用面仅占种群的 1%（2/200），
且每代仅产生 ≤2 条经验，单个 episode 约 2000 条样本、按 `batch_size=128`
只能触发约 15 次更新。这是该设计在样本效率上的固有短板。

## 4. 结果

### 4.1 实验1：消融

控制器固定为 Q-learning，逐级开启 MSI / VNS / EP，使差异只来自进化模块本身
（论文 Table 6 的做法）。v4 即 MOEQLF，MOECLF 为在同一框架上再加 PPO。

**HV 均值（6 实例 × 5 种子）**

| 配置 | HV 均值 | 逐级增量 | vs 上一级的 p |
|---|---:|---:|---:|
| v1 基线 | 0.412 | — | — |
| v2 +MSI | 0.477 | +0.065 | 7.73e-02 |
| v3 +VNS | 0.392 | **−0.085** | 1.03e-02（**显著更差**） |
| **v4 +EP (=MOEQLF)** | **0.891** | **+0.499** | 3.02e-11 |
| MOECLF +PPO | 0.867 | −0.024 | 1.02e-01 |

**逐实例 HV**

| 实例 | v1 基线 | v2 +MSI | v3 +VNS | v4 +EP | MOECLF |
|---|---:|---:|---:|---:|---:|
| J15-S2-1 | 0.435 | 0.433 | 0.338 | 0.841 | 0.800 |
| J15-S4-1 | 0.329 | 0.349 | 0.277 | 0.876 | 0.839 |
| J30-S2-1 | 0.431 | 0.460 | 0.446 | 0.898 | 0.894 |
| J30-S4-1 | 0.487 | 0.584 | 0.455 | 0.890 | 0.867 |
| J45-S4-1 | 0.255 | 0.409 | 0.364 | 0.876 | 0.863 |
| J45-S6-1 | 0.535 | 0.625 | 0.471 | 0.966 | 0.939 |

**集合覆盖率 C**

| C(U,V) | v1 | v2 | v3 | v4 | MOECLF |
|---|---:|---:|---:|---:|---:|
| **v1** | — | 0.088 | 0.191 | 0.000 | 0.000 |
| **v2** | 0.736 | — | 0.630 | 0.000 | 0.000 |
| **v3** | 0.558 | 0.181 | — | 0.000 | 0.000 |
| **v4** | 1.000 | 1.000 | 1.000 | — | 0.439 |
| **MOECLF** | 1.000 | 1.000 | 1.000 | 0.280 | — |

**解读**

1. **EP 是唯一的主要贡献，且幅度极大**：v3→v4 使 HV 从 0.392 升至 0.891
   （+0.499，p=3.02e-11），覆盖率 C 达到 1.000——v4 完全支配前三个配置。
   这一项单独解释了绝大部分性能提升。
2. **MSI 有正向贡献但未达显著**：v1→v2 为 +0.065，p=7.73e-02；
   覆盖率 C 为 0.736（v2 支配 v1）。方向一致但功效不足。
3. **VNS 在本复现中显著为负**：v2→v3 为 **−0.085**（p=1.03e-02），
   且 v2 对 v3 的覆盖率为 0.630。开启 VNS 后动作空间从 3 个扩到 10 个，
   在 Q-learning 尚未充分收敛的情况下引入了更多劣质算子。
4. **PPO 仍未带来增益**：v4 vs MOECLF 为 −0.024，p=1.02e-01，方向与实验2、3 一致。

> 注：本表的 v4（0.891）与实验3 的 MOEQLF（0.828）数值不同，原因是归一化的
> 参考集在本实验内构造（含较弱的 v1/v2/v3，拉低了 fmin/fmax）。**跨表比较绝对值无意义**，
> 只应引用同一张表内的对比。

## 5. 结论

### 5.1 站得住的正面结论

| 结论 | 强度 |
|---|---|
| **协同学习框架整体显著优于 MODJA、NSGA-II**：C 达 0.944，p≈1e-11 | 强 |
| **框架在 6 个测试实例上表现一致**，无明显规模退化 | 强 |
| **精英保留（EP）是框架性能的主要来源**：v3→v4 提升 +0.499，p=3.02e-11 | 强 |
| **MSI 方向为正**（+0.065），但未达显著（p=0.077） | 中 |

### 5.2 未能复现的部分

| 结论 | 证据 |
|---|---|
| **PPO 未带来增益** | 实验2 中 Q-only vs PPO+Q，p=0.119，无显著差异 |
| **PPO 甚至略差** | 实验3 中 MOECLF 0.790 < MOEQLF 0.828，p=0.047 |
| **学习型控制器未超过随机算子选择** | 实验2 中 Q-only、PPO+Q 相对 Random 的 p 分别为 0.045、6.9e-4 |
| **VNS 未带来增益** | 实验1 中 v2→v3 为 −0.085，p=0.010，显著更差 |

### 5.3 对论文核心创新点的判断

论文的核心创新是「PPO + Q-learning 双智能体协同」。在严格遵循两阶段协议的前提下，
复现结果**未能支持 PPO 模块的增益**：

```
实验2   Q-only 0.661  vs  PPO+Q 0.621      p=0.119   无显著差异
实验3   MOEQLF 0.828  vs  MOECLF 0.790     p=0.047   PPO 反而更差
```

需要强调的是：**这一结论并不意味着论文的方法有误**，而更可能与以下两点有关：

1. **PPO 的作用面过小**。它只接管 2/200 个个体，且每代仅产生 ≤2 条经验，
   单个 episode 约 2000 条样本、约 15 次参数更新。对约 2.2M 参数的
   MobileNetV2 而言，这个样本量偏少。
2. **奖励信号稀疏**。式(38) 中真正表示帕累托改进的 `reward=+2`
   在实际执行中占比较低，多数动作只能达到「互不支配」（+1），
   难以提供明确的优化方向。

同时，Q-learning 在状态设计上只看「上一个算子」，不含调度状态，
其决策能力本身也有限——这解释了为什么两个学习型控制器都未能超过随机基线。

### 5.4 关于 Random 反超的说明

「随机算子选择优于学习型控制器」这一结果看似反直觉，但与框架结构一致：
MOECLF 的性能主要来自 **MSI + VNS + EP** 这套进化机制本身，
算子选择的差异在 1000 代的精英保留下会被大幅稀释。
这也提示：若要提升该框架，投入方向可能是**算子池设计**与**精英保留策略**，
而非算子选择的学习算法。

## 6. 与原文的差异和已知局限

### 6.1 已知偏差

| 项目 | 原文 | 本复现 | 影响 |
|---|---|---|---|
| **测试实例的独立性** | 应为训练阶段未见过的实例 | 测试集含 `J45-S6-1`，它在训练集内 | ⚠️ 见下 |
| 运行设备 | 服务器 GPU | 本地 CPU | 不改变算法语义 |
| 统计样本量 | 未明确 | 6 实例 × 5 种子 | 检验功效偏小 |

**训练/测试实例重叠**：`J45-S6` 系列在官方数据集中仅有 10 个实例，
因此训练集取 `J45-S6-1..10` 时，测试集若要覆盖 6 阶段规模就必然与之重叠。
`J45-S6-1` 在训练阶段被完整训练过 1 个 episode，之后又用于测试。

按当前结论这不影响判断方向（该实例上 PPO+Q 的 HV 为 0.642，
仍低于 Random 的 0.830），但**不应基于该实例的结果论证正向结论**。
若要彻底消除重叠，需把测试集换成其余规模（如只用 J15/J30 系列），
或在训练集中排除该实例后重跑训练阶段。

### 6.2 统计与方法局限

1. **n=6 的检验功效弱**。p 值未达显著只说明「无证据显示有差异」，
   不能断言「绝对无差异」。
2. **归一化参考集各实验独立构造**，导致同一配置在不同实验中的绝对值不同。
   横向跨实验比较无意义，需统一参考集才能比较。
3. **测试阶段仍带随机性**。`train=False` 只关闭参数更新，
   Q-learning 仍保留 `eps=0.4` 探索、PPO 仍按分布采样。
   因此结果是策略的期望表现，而非确定性输出。
4. **训练阶段只跑 10 个 episode**（每实例 1 个），与论文一致，
   但未做收敛性验证（如增加 episode 数观察性能曲线）。

```
Python 3.12.14
```

### 7.2 运行

```bash
python run.py smoke              # 全链路冒烟测试（秒级）
python run_experiments.py        # 训练阶段 + 测试阶段 + 汇总（实验2、3）
```

× 各算法）→ 汇总写表。中间结果缓存在 `results/_model/` 与 `results/_cache/`，
中断后重跑会自动跳过已完成的部分。`run_ablation.py` 复用主实验的 v4 与 MOECLF
模型和前沿，只需补跑 v1/v2/v3。
