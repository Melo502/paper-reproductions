# 实验 A：PPO 上限实验（Oracle 完美选择器）

> 规模：Np=200 / Ngen=1000，5 种子 × 6 实例
> Oracle = 对 2 个边界个体枚举全部 10 个 LLH 并取最优，代表 PPO 的理论上限
> Random / Q-only / PPO+Q 复用 run_experiments 论文规模缓存（同种子天然配对）

## 表2 配对差值汇总（每实例各控制器取种子均值）

| 对比 | HV 平均差 | Oracle/前者胜出 | Wilcoxon signed-rank p |
|---|---:|---:|---:|
| Oracle vs Q-only | +0.0293 | 5/6 | 0.219 |
| Oracle vs Random | -0.0319 | 2/6 | 0.219 |
| Oracle vs PPO+Q | +0.0106 | 4/6 | 0.562 |
| PPO+Q vs Q-only | +0.0187 | 3/6 | 0.562 |
| PPO+Q vs Random | -0.0425 | 1/6 | 0.156 |

## 结论判定

- Oracle − Q-only = **+0.0293**（5/6 胜，p=0.219）
- Oracle − Random = **-0.0319**（2/6 胜，p=0.219）
- Oracle − PPO+Q = **+0.0106**（4/6 胜，p=0.562）

显著性水平 α=0.05（Wilcoxon signed-rank，n=6 个实例，统计功效有限）

**判定：2/200 边界位置基本没有提升空间。** 即使每次都为边界个体枚举全部 10 个 LLH
并挑 reward 最大的（= 完美选择器），HV 也仅比 Q-only 高 +0.0293，
p=0.219 不显著；而且比纯 Random 还低 -0.0319。

这意味着：**PPO 负责的那 2 个边界个体，其动作选择不是性能瓶颈。**
即便 PPO 训练得完美无缺，也无法把 HV 拉起来 —— 增益被结构性地限制住了。
PPO 路线在现有「2/200 分工」设计下没有空间，建议转向实验 B（让 PPO 接管全部个体）
或实验 E（简化观测），而不是继续在样本量/超参上加投入。

### 附：奖励信号的稀疏程度（表3 佐证）

Oracle 已取每步**最大**可达 reward，但 `reward=+2`（支配改进）的占比仍只有 0.7%–2.6%，
说明即便完美选择，绝大多数动作也只能做到非劣（reward=+1）—— 该奖励函数本身几乎不提供「改进方向」的梯度信息。
