## 🎯 复现目标

论文研究 **人机协作的节能混合流水车间调度问题（EHFSP-HMC）**，提出 **多目标进化协同学习框架（MOECLF）**：用 PPO 与 Q-learning 双智能体选择低层启发式（LLH），驱动多目标进化搜索，通过“进化—学习”闭环增强搜索能力。

本复现依据论文公式与流程图**独立实现**（非作者代码），并严格遵循论文的**两阶段协议**：先在 10 个训练实例上完成训练阶段，再在 6 个测试实例上以冻结策略执行测试阶段。

## 🧠 算法设计说明

三个被比较的控制器共享**完全相同**的 MOECLF 进化框架，只在“由谁选择算子”上不同。因此它们的差异可干净地归因于算子选择策略。

| 组件 | 三者是否一致 |
|------|:---:|
| 多策略初始化 MSI（9 条规则组合） | ✅ |
| 算子池：3 个遗传算子 + 7 个 VNS 局部搜索算子（LLH1–10） | ✅ |
| 非支配排序 + 拥挤距离 | ✅ |
| 交叉父代选择（Algorithm 5） | ✅ |
| 精英保留 EP | ✅ |
| **算子选择策略** | ❌ 差异所在 |

### Random：随机算子选择（下界参照）

每个个体每代从 10 个 LLH 中**均匀随机**抽取一个执行，不接收奖励、不更新参数（`moeclf.py` 的 `controller == "random"` 分支中既无 `reward()` 也无 `update()`）。

**设计原因**：

1. **界定“学习”的净增益**。它保留完整框架，只把算子选择换成随机，因此与学习型控制器的差距就是算子选择这一项的贡献，不会被框架本身的强度掩盖。
2. **它控制全部 200 个个体**（而非只控制 2 个边界个体）。因此 Random 与 PPO+Q 的差异同时包含“有无学习”和“控制范围”两个因素，不能全部归因于 PPO。
3. **命名注意**：它不是经典 Random Search（随机生成解、择优保留），而是**随机算子选择**，正文宜写 “Random LLH selection”。

### Q-learning：表格型控制器（承担 198/200）

状态 = 上一步执行的算子（0–9），动作 = 下一步算子（0–9），Q 表为 **10 × 10 = 100 格**；ε-贪心（`eps=0.4`）探索，更新式 `Q[s,a] += alpha * (r + gamma * max Q[a,:] - Q[s,a])`。

**设计原因**：

1. **样本效率**。它每代负责 200 个个体中的 198 个，单个 episode 即产生约 20 万次更新；100 格的表在这个量级下会迅速收敛。若换成百万参数的深度网络，同样样本量远不足以训练。
2. **状态空间本就很小**。“上一步算子”只有 10 种取值，表格可精确表示，无需函数近似。
3. **与 PPO 互补分工**。它负责数量占绝对多数的普通个体，追求稳定、廉价的决策；PPO 负责少数关键个体，追求更强的状态感知。

**代价**：状态只看“上一个算子”，不含调度状态与目标值信息，对问题结构的感知很弱。

### PPO+Q：双智能体协同（论文核心创新）

200 个个体按角色分工，PPO 只接管**边界个体（BI）**：

```
200 个个体
├── 198 个 → Q-learning
└──   2 个 → PPO        （F1 前沿上拥挤距离最大的 2 个）
```

两个 PPO agent 分别负责 `Cmax` 较小与较大的两端，各配一个**手写 MobileNetV2**（约 2.2M 参数），输入为 **46 × 46 的 FSM 图像**（行 = 机器 + 工人状态，列 = 作业 + 目标值），输出 10 个算子的策略分布。

**设计原因**：

1. **边界个体决定前沿覆盖范围**。F1 上拥挤距离最大的个体位于前沿两端，向目标空间稀疏区域延展，直接决定 HV 上界，把最强决策能力放在这里符合“好钢用在刀刃上”。
2. **PPO 需要丰富状态信息**。FSM 图像编码机器负载、工人疲劳、目标值等全局状态，适合卷积网络；若 198 个普通个体也走 PPO，算力开销无法承受（单次前向约 12 ms）。
3. **奖励对应帕累托改进**（式 38）：

   | 子代相对父代 | reward |
   |---|---|
   | 子代支配父代 | **+2** |
   | 父代支配子代 | **−1** |
   | 互不支配 | **+1** |
   | 完全相同 | 0 |

**代价**：作用面仅占种群 1%（2/200），且每代仅产生 ≤2 条经验，单个 episode 约 2000 条样本、按 `batch_size=128` 只能触发约 15 次更新，样本效率存在固有短板。

## 📈 复现结果

HV 均值（6 实例 × 5 种子），完整数据与逐实例表格见 [`Code/REPORT.md`](./Code/REPORT.md)。

### 结论速览

| 论文结论 | 复现结果 | 是否一致 |
|----------|----------|----------|
| 协同学习框架优于 MODJA、NSGA-II | 覆盖率 C 最高 0.944，p ≈ 1e-11 | ✅ 一致 |
| 精英保留（EP）提升性能 | v3→v4 提升 +0.499，p = 3.02e-11，C = 1.000 | ✅ 一致 |
| MSI 提升性能 | +0.065，p = 0.077（方向为正，未达显著） | 🟡 部分一致 |
| VNS 提升性能 | v2→v3 为 −0.085，p = 0.010（显著更差） | ❌ 未能复现 |
| PPO 控制器带来增益 | Q-only vs PPO+Q 无显著差异（p = 0.119）；算法对比中 MOECLF 显著更差（p = 0.047） | ❌ 未能复现 |
| 学习型控制器优于随机算子选择 | Q-only、PPO+Q 均低于 Random（p = 0.045、6.9e-4） | ❌ 未能复现 |

### 实验 1：消融

控制器固定为 Q-learning，逐级开启 MSI / VNS / EP，使差异只来自进化模块本身。

| 配置 | HV 均值 | 逐级增量 | vs 上一级的 p |
|------|--------:|---------:|--------------:|
| v1 基线 | 0.412 | — | — |
| v2 +MSI | 0.477 | +0.065 | 7.73e-02 |
| v3 +VNS | 0.392 | **−0.085** | 1.03e-02（显著更差） |
| **v4 +EP (= MOEQLF)** | **0.891** | **+0.499** | 3.02e-11 |
| MOECLF +PPO | 0.867 | −0.024 | 1.02e-01 |

**EP 是唯一的主要贡献**：v3→v4 使 HV 从 0.392 升至 0.891，覆盖率 C 达 1.000（v4 完全支配前三个配置）。MSI 方向为正但未达显著；VNS 在本复现中显著为负——开启后动作空间从 3 个扩到 10 个，在 Q 表尚未充分收敛时引入了更多劣质算子。

> 本表 v4 为 0.891，实验 3 的 MOEQLF 为 0.828，差异来自归一化参考集在本实验内构造（含较弱的 v1/v2/v3）。**跨表比较绝对值无意义**，只应引用同一张表内的对比。

### 实验 2：控制器对比

| 配置 | HV 均值 | vs Random 的 p |
|------|--------:|---------------:|
| **Random** | **0.7215** | — |
| Q-only | 0.6610 | 4.51e-02（更差） |
| PPO+Q | 0.6210 | 6.91e-04（更差） |

两个学习型控制器均未超过随机算子选择；Q-only 与 PPO+Q 之间无显著差异（p = 0.119），这是评价 PPO 的**干净对照**。

### 实验 3：算法对比

| 配置 | HV 均值 | C（支配 NSGA-II 的比例） |
|------|--------:|-------------------------:|
| MODJA | 0.5165 | 0.134 |
| NSGA-II | 0.5773 | — |
| **MOEQLF** | **0.8280** | 0.944 |
| MOECLF | 0.7897 | 0.893 |

MOEQLF/MOECLF 显著优于两个基线（p ≈ 1e-11），但 MOECLF 显著低于 MOEQLF（p = 0.047）——加入 PPO 反而使结果变差。

## ⚠️ 与论文的差异

| 项目 | 原文 | 本复现 | 影响 |
|------|------|--------|------|
| 测试实例的独立性 | 应为训练阶段未见过的实例 | 测试集含 `J45-S6-1`，它在训练集内 | 见下 |
| 运行设备 | 服务器 GPU | 本地 CPU | 不改变算法语义 |
| 统计样本量 | 未明确 | 6 实例 × 5 种子 | 检验功效偏小 |

**训练/测试实例重叠**：`J45-S6` 系列在官方数据集中仅有 10 个实例，因此训练集取 `J45-S6-1..10` 时，测试集若要覆盖 6 阶段规模就必然与之重叠。`J45-S6-1` 在训练阶段被完整训练过 1 个 episode，之后又用于测试。

按当前结论这不影响判断方向（该实例上 PPO+Q 的 HV 为 0.642，仍低于 Random 的 0.830），但**不应基于该实例的结果论证正向结论**。

**其他局限**：

- **n = 6 功效弱**：p 值未达显著只说明“无证据显示有差异”，不能断言“绝对无差异”。
- **归一化参考集各实验独立构造**：同一配置在不同实验中的绝对值不同，**跨表比较无意义**，只能引用同表内的对比。
- **测试阶段仍带随机性**：`train=False` 只关闭参数更新，Q-learning 保留 `eps=0.4` 探索、PPO 仍按分布采样，结果是策略的期望表现。
- **训练阶段只跑 10 个 episode**（每实例 1 个），与论文一致，但未做收敛性验证。

**对论文核心创新点的判断**：论文的创新是“PPO + Q-learning 双智能体协同”。在严格遵循两阶段协议的前提下，复现结果未能支持 PPO 模块的增益。这一结论并不意味着论文方法有误，更可能与两点有关：PPO 作用面过小（2/200，每代 ≤2 条经验）、以及奖励信号稀疏（`reward=+2` 占比低）。同时 Q-learning 的状态设计只看“上一个算子”，不含调度状态，决策能力本身也有限——这解释了为何两个学习型控制器都未超过随机基线。

## 🔑 关键概念速查

- **EHFSP**：混合流水车间调度问题（Hybrid Flow-Shop Scheduling Problem）
- **HMC**：人机协作（Human-Machine Collaboration）
- **MOECLF**：多目标进化协同学习框架
- **MOEQLF**：去掉 PPO、仅用 Q-learning 的版本
- **LLH**：低层启发式（Low-Level Heuristic），作为 RL 的动作空间
- **FSM**：可行解矩阵（Feasible Solution Matrix），用于状态表示
- **BI**：边界个体（Boundary Individual），拥挤距离最大的个体，由 PPO 负责
- **EP**：精英保留（Elitist Preservation），环境选择
- **MHV / HV**：超体积指标（HyperVolume），衡量解集收敛性与多样性
